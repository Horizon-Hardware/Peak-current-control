# 底盘超级电容充放电简版

入口仍为 `ADC_Convert()` → `Loop_Control()`。默认电容目标28 V、电池总功率60 W、电池平均限流5 A；充电参考0～15 A，放电谷值参考−15～+2 A（正偏置仅用于零点校正，硬件方向由`power_request`确定）。参考数值不等于实测电感/电容平均电流。

当前满电行为：目标28 V时，满电后保持停充，回落到27.5 V再补充，满电保持不阻挡底盘超预算时的放电。正向Boost最大比较点13600，为22 V输入升28 V留压降和死区余量。2026-11-15后续修正：Buck斜坡步长从本轮开始时的180调整为360，Boost保留180；详见文末“70 W小功率补能与剩余抖动”。

2026-11-15新增：实际模式调制使用±0.015电压比回差；功率平衡点采用充电/停止/放电三态回差。60 W预算时，从停止状态到≤58 W才恢复充电、到≥62 W才开始放电；充电时升到59.5 W、放电时降到60.5 W先停止。平衡区允许接近±2 W的预算偏差，以减少反复换向；这是新增的稳定性取舍，不是严格60.000 W的硬功率钳位。

## 当前控制关系

```text
电池功率PI → 电池总电流参考 I_BAT_ref
                          ↓
I_BAT_ref − 实测I_BAT → 电流PI ─┐
V_target − V_CAP     → 电压PI ─┴→ 取小 → 有符号I_target → 两路DAC/PWM
```

沿用原有功率外环与电流/电压双环竞争，不使用负载前馈。电流环反馈仍来自电池总电流I_BAT；充电由电流/电压PI取小，放电由电流PI独立调谷值参考，避免充电电压环截断正的零点修正。`loop_var.power_request`决定硬件方向，放电还要求电容高于10 V。停充停放区关闭PWM、清零电流PI，功率PI跟踪实际底盘需求并暂停积分。

电池预算为 `min(P_BAT_target, V_CHASS * I_BAT_target)`。原始底盘功率仍按 `V_CHASS * (I_BAT-I_LL)` 显示；PI与判向使用匹配的一阶电流滤波，保留原始ADC值供调试。电流/电压PI保持20 kHz，功率PI保持200 Hz，实际功率预算也作为功率PI目标；首次运行与截止恢复时，用预算/V_CHASS给功率PI设置初值。

电压PI未接管时，输出跟踪“非负的最终请求＋Kp×电压误差”，保留比例余量；电压PI接管时保留它自己计算出的状态。这样避免电流请求短暂归零就把电压PI也反复清零，同时保留28 V恒压限制。

## 放电截止与80%恢复

- 电容≤10 V，且当前为放电方向或底盘仍超预算：立即关闭四路PWM，置 `loop_var.discharge_cutoff=1`。
- 截止后保持停机；电容电压自己恢复不能解除。
- 底盘功率严格低于电池预算的80%时解除截止，恢复充电。
- 60 W预算时：底盘50 W保持停机，48 W仍保持停机，低于48 W才恢复。
- 解除截止后允许从低于10 V的电容电压重新充电。

这里的80%恢复条件只针对10 V放电截止锁停。正常放电回落到平衡区时先停止补能，跨过新的充电进入阈值后恢复充电，不必等到80%。电容已耗尽而底盘仍超预算时，软件只能停止变换器，不能阻止并联底盘继续向电池取电。

## 方向切换

充电使用下降DAC斜坡与原峰值控制。放电使用上升DAC斜坡，HRTIM的EEV1/EEV4改为低有效，同时交换TA1/TB1的储能开始/结束事件。COMP1/2保持非反相，两侧驱动保持高有效、180°相移和互补死区。按现有硬件，不能只改DAC斜坡而不改变PWM事件关系。

换向时执行：四路PWM全关 → 更换方向配置 → 返回 → 下次50 μs控制调用按当前请求启动。硬件方向由功率回差需求确定，谷值PI接近零或稍为正不会更换方向。不读取过零比较器窗口，没有多阶段换向等待、负载前馈或电流缓升缓降。固定50 μs间隔需要结合现有10 μH电感、约24 V母线和门极波形上板确认，本次没有实测换向波形。

两路DAC/CMP的Buck/Boost调制沿用此前结构；充电按V_CAP/V_CHASS，放电按V_CHASS/V_CAP映射。过渡进度现在经过下述滤波、保持带和限速，两路DAC使用S形交接。±15 A既限制PI指令，也限制主控侧斜坡补偿后的初始阈值范围。仍存在消隐、纹波和模拟延迟，不能把软件15 A限幅当作实际电流绝对不越过15 A的保证。

30 V锁停、无效输入停机，以及充电目标附近±0.05 V的PWM启停回差保留。CubeMX保持当前充电启动配置，本次无须修改。

## 2026-11-13：Buck/Boost双向过渡优化

针对充放电经过等压附近的振荡，本次仅修改`User/task.c`、`User/task.h`中的模式调制及本说明。保留上板现有PI参数（电流Ki=0.0055、功率Ki=0.0055）和两路180的DAC步长，保留180°相移、原PWM事件、15 A指令上限、10 V截止及80%恢复。

原调制把每次电压比变化直接传给两路DAC/CMP；两路阈值在`blend=0.5`附近的交接曲线还有斜率突变。这些是软件中可确认的敏感点，尚不能据此断定实物振荡只有这一个原因。

本次处理：

1. **仅对模式电压比滤波**：`mode_ratio_filtered += 0.1 * (ratio-mode_ratio_filtered)`。20 kHz调用下时间常数约0.5 ms。电压PI、电流PI继续使用原采样，电流指令不加缓升缓降。
2. **进度保持带**：目标与当前`blend`相差不超过0.01时，保持当前进度，减少噪声导致的来回调制。纯Buck/Boost端点仍允许收敛到精确的0/1。
3. **交接限速**：PWM运行时每50 μs最多改变0.01进度。完整0→1交接至少5 ms；这是模式参数的限速，不是给电流环增加5 ms等待。
4. **S形DAC交接**：原来两处线性`Clamp()`权重改成`SmoothStep(x)=x*x*(3-2*x)`，两端斜率为0，使`blend=0.5`处DAC交接更平缓。充电、放电使用相同处理。
5. **重启与换向重新定位**：PWM关闭时按新方向的当前电压比初始化滤波和进度，避免把充电进度直接用到反向放电。

保留原过渡边界0.85～1.05。24 V输入充电时，对应CAP 20.4～25.2 V；CAP=24 V时进度约0.75。四个模式名称是这条连续曲线上的区域标记，并没有在24 V重新切换比较器/PWM事件配置。

新增可调参数集中在`User/task.h`：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `MODE_RATIO_FILTER_ALPHA` | 0.10 | 越小越能抑制模式电压比的高频噪声，但交接跟踪更慢 |
| `MODE_BLEND_MAX_STEP` | 0.01 | 每次控制调用允许的最大进度变化 |
| `MODE_BLEND_DEADBAND` | 0.01 | 进度保持带，24 V充电时约对应48 mV |

调试观察`loop_var.Duty`（原始电压比）、`mode_ratio_filtered`（模式滤波值）、`mode_blend`（实际进度）、`I_target`和`pwm_enabled`。若等压附近仍振荡，区分“进度已平稳、电感电流仍隔周期变化”和“PWM反复启停/PI请求摆动”，再决定调整斜坡或PI，避免只扩大模式回差。

## 满电保持与22 V升压（2026-11-13最新）

此前目标附近±0.05 V启停，加上很小的电流请求启停阈值，会在满电附近形成短脉冲补充。满电后电容无法继续吸收预算内的全部功率，此时电池功率应回落到负载实际需要，不能强求继续60 W。

本次新增`loop_var.charge_complete`：CAP≥目标+0.05 V，或目标附近CV输出已经趋零时进入保持；CAP≤目标-0.5 V才解除。28 V目标对应约27.5～28.05 V的补充区间。保持时PWM关闭、电流PI归零、功率PI暂停并跟踪底盘需求，电压PI让位，避免误差累积及恢复时慢慢积分。底盘超预算时跳过满电保持，原补能逻辑立即处理。

这是一种满电停充/回差补充方式，允许电容电压在区间内变化，不是连续紧贴28.000 V的浮充。CAP有持续负载时仍会周期补充，周期取决于容量和负载；空载满电则应保持停止。恢复触发点为27.5 V，动态下冲还与电流建立速度有关。

当前`BOOST_CMP_MAX=13600`。原10000对应22 V输入约28.16 V的理想电压上限，真实压降和死区后没有足够28 V调节余量。两路起始阈值的补偿也随窗口宏同步变化。反向新增独立的`DISCHARGE_BOOST_CMP_BASE=10000`，保持其原来的动态窗口下限，正向扩展不改变反向窗口。

原来新增的固定25 V以下只标记CC、实际仍取小的代码已修正：用相对目标的`CAP_CV_WINDOW_V=0.2 V`限定恒压接管区，区外电压环让位，实际输出与模式标记保持一致。28 V目标时，低于27.8 V先由电流环建立充电电流，进入目标附近后继续CV/CC取小。

调试看`charge_complete`、`pwm_enabled`、`I_target`：满电且底盘未超预算时，应为1、0、0。此时`PI_Volt_Controller.output`置于让位上限，并不意味着施加15 A；实际请求为0，PWM关闭。底盘超预算后允许负请求，不必等CAP跌到27.5 V。硬件换向仍保留原来的一个50 us关断间隔。

两路DAC步长使用用户当前值200，主程序PI参数、CubeMX及30 V保护保持原配置。本次备份`build/cv-22v-before-20261113/`。此前被中断的满电排查只保存过`build/full-charge-before-20261113/`备份，没有完成生产修改。

编译与回归检查通过。22/24 V输入、CAP空载/8 W带载的含80 ns死区理想模型均能达到28 V附近；空载满电后不再重启，8 W负载按回差补充。模型不包含全部硬件误差，实物升压余量和波形需复测。详细模型参数、范围及运行命令见`build/cv-22v-validation/README.md`。

### 电压比回差作用于实际调制

模式滤波值继续使用原来的0.10系数。新增`mode_ratio_applied`保存上一次实际使用的电压比：滤波值与保存值相差不超过`MODE_RATIO_HYSTERESIS=0.015`时保持；超出后沿回差边缘连续跟随。随后仍按0.85～1.05映射进度、每次最多变化0.01，并使用原S形DAC交接。

这不是只让模式名称少跳动：充电、放电的DAC阈值和CMP窗口都由这个带回差的值决定；放电动态Boost窗口也改用它，避免窗口仍从另一条未经回差的路径随噪声变化。停机重启或硬件换向时，按新方向当前电压比重新定位，不继承旧方向的历史。

在缓慢扫压、PWM持续运行且已进入跟随分支时，三个分界的理论门槛如下；滤波与进度限速会产生少量动态滞后。启动时直接按当前比值定位。

| 分界 | 电压比上升门槛 | 电压比下降门槛 |
| --- | --- | --- |
| Buck / BuckBoost | 0.865 | 0.835 |
| BuckBoost / BoostBuck | 0.965 | 0.935 |
| BoostBuck / Boost | 1.065 | 1.035 |

充电电压比为`V_CAP/V_CHASS`，24 V输入时单边回差约0.36 V，完整往返宽度约0.72 V。放电比值为`V_CHASS/V_CAP`，对应CAP电压不能直接套用充电的伏数。例：24 V母线、CAP约24 V时，电压比在1附近的小变化会保持模式参数；明显变化仍可连续跟踪。电流指令不经过该回差或额外限速。

### 功率平衡区减少反复换向

以有效电池预算60 W为例：

| 当前请求状态 | 底盘功率条件 | 下一状态 |
| --- | --- | --- |
| 停充停放 | ≤58 W | 充电 |
| 停充停放 | ≥62 W | 放电补能 |
| 充电 | ≥59.5 W且<62 W | 停充停放 |
| 放电 | ≤60.5 W且>58 W | 停充停放 |
| 任一状态 | ≤58 W或≥62 W | 直接选择对应充电/放电请求 |

回差取`min(2 W, 有效预算×5%)`，退出幅值为进入幅值的25%，所以小预算不会被固定2 W死区完全压住。有效预算仍取`min(P_BAT_target, V_CHASS*I_BAT_target)`。

充电请求把电流PI限制为0～15 A，放电请求限制为−15～0 A，原始功率不再另行逐次裁剪电流符号。平衡区先停PWM、清零电流PI并暂停功率积分，以免在60 W附近反复换向并由积分积累出脉冲。代价是平衡区的电池功率可以略高于或低于设定值：60 W预算时，从停止状态允许接近58～62 W；若需要更小误差可减小`POWER_BALANCE_ENTER_W`，但抗噪能力随之下降。

`PowerStage_Apply()`额外使用现有PWM启动幅值0.05 A作为硬件换向门槛，±0.02 A之类的小请求不再反复改DAC极性；同方向请求降至0.01 A时停PWM。明显反向请求仍保留原来的一个50 μs关断间隔，没有新增确认计时或电流缓升缓降。

## 2026-11-15后续：70 W小功率补能与剩余抖动

本轮以用户实测和当前工程为依据。修改前备份为`build/support-70w-before-20261115/`，其中两路斜坡均为用户当时的180。

实测问题为：CAP约27 V、底盘约70 W、电池约70 W、`I_target≈−0.04`、`pwm_enabled`反复0/1、`discharge_cutoff=0`。可确认没有触发10 V截止，但PWM正在反复启停。旧代码要求负参考达到−0.05 A才启动、升回−0.01 A即停止，还用参考符号判向。谷值参考叠加斜坡补偿后不等于平均电流；若所需小放电恰好对应零附近参考，上述条件会使PI与PWM启停互相干扰。不能据这组数值断言实物零点偏置的具体大小。

本次修改：

1. `PowerStage_Apply()`从`power_request`确定硬件方向。处于放电需求时，即使谷值参考为−0.04 A、零或小幅正值，也持续更新DAC并保持PWM；由功率回差退出、10 V截止及原有保护负责停止。充电仍保留原有满电保持和微小请求停充。
2. 放电电流PI范围从−15～0 A扩展为−15～+2 A，DAC的基础码同时允许正偏置。正偏置用于修正斜坡/电流纹波造成的平均电流零点差，不表示改成充电PWM；实际流向和功率应看`I_LL`/`P_LL`。放电时绕过充电电压PI取小，避免正修正被截断。默认+2 A是调节余量，不是要求电容充2 A。
3. 电池、DCDC支路电流分别按`filtered += 0.25*(raw-filtered)`处理，两者系数一致；20 kHz下等效时间常数约0.15 ms。电流PI、功率PI和功率回差使用该反馈，原始ADC及功率显示不覆盖。此项会增加约亚毫秒量级的反馈延迟，减少采样噪声直接进入PI。
4. Buck斜坡由180增加到360，充电A侧/放电B侧共用；Boost保留180。起始阈值补偿随宏一起更新。斜坡加强会改变同一平均电流对应的`I_target`并降低硬件内环增益，需由原外环修正；电流PI参数保持原值。
5. 功率PI实际目标统一为有效预算`min(P_BAT_target, Vin*I_BAT_target)`，避免平均限流较低时仍对不可达到的原始功率目标继续积分。

60 W平衡回差和电压比±0.015迟滞保留，模式滤波、S形交接及5 ms最短完整交接保留。PWM仍200 kHz、两桥180°相移，充电28 V目标、30 V锁停、10 V截止及严格低于80%恢复保持。CubeMX无需修改。

验证使用`python tools/control-hysteresis-tests/run.py --switch`，日志在`build/hysteresis-validation/`。新增27 V/70 W平均模型，分别设置0 A和1 A的“谷值参考到平均电流”偏置，两种情况下都能将电池调到60 W附近，稳定段没有PWM重启；后一种情况下PI为小正值但硬件始终放电，用于覆盖旧启停逻辑的盲区。这是人为设置的模型偏置，并非实物测量。

另以固定CAP电压的10 ns开关模型扫描18～27 V充电和10.5～27 V放电，含±0.1 V采样扰动、10 μH/80 mΩ、80 ns理想死区。基线两路180与新Buck360的比较中，18 V充电的同周期末电流标准差约0.713→0.078 A，27 V/70 W放电约0.386→0.267 A；24 V点基本持平。不是所有点均改善，20.4 V充电的功率标准差略有增加；不能把这些模型数字当成实际电流纹波或实物稳定性证明。模型没有复现全部实物零点/ADC/驱动误差。

重新上板重点看27 V电容、70 W负载时：`power_request=-1`、`energy_direction=-1`、`pwm_enabled`应持续为1，电池应向60 W收敛、`P_LL`应约为−10 W（CAP实际消耗还包括变换损耗）。`I_target`可在负值到小正值范围内校正，不应据此自行停PWM。若正修正持续顶到+2 A而电池仍明显低于目标，说明零点/斜坡偏置超出当前余量，需要结合实测再调整。
