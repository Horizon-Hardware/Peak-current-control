### 大负载读取失败时的对照方法

已捕获到 OpenOCD 错误 `Fail reading CTRL/STAT register. Force reconnect`。这发生在调试端口访问阶段，不能把调试器显示的零地址直接当成有效 PC。用户反馈 CubeCLT 低频刷新时正常，因此需分别比较采样频率、驱动实现和硬件干扰，尚未确定唯一原因。

如果当前连接已经稳定，保留正在使用的调试服务。若再次掉线，可先取消“高速采样”，将周期设为 **1000 ms**，仅勾选 `adc_data.volt.V_CAP` 和 `adc_data.power.P_BAT`，在相同负载下比较。稳定后再按 `1000 → 500 → 200 → 100 ms` 逐步提高采样频率。

若 1000 ms 仍失败，本工程另已添加 **OpenOCD HLA Wave Scope** 服务，使用 `config/stm32g474-stlink-hla-live.cfg`。结束原来的调试连接后，从顶部调试服务下拉框切换到它，保持同一采样周期和变量再比较。若列表没有出现，重新打开工程以加载新增服务。两种服务使用相同端口，只运行其中一种。

HLA 是该 OpenOCD 安装中提供的另一种 ST-Link 驱动；配置语法已验证，但尚未用它初始化实物探头或完成大负载采样验证。启动时的 `DEPRECATED` 提示说明上游计划移除该驱动，不代表本次配置解析失败。

## 4. 添加与查看变量

默认已经加入：

```text
adc_data.volt.V_CAP
adc_data.power.P_BAT
adc_data.power.P_CHASS
loop_var.I_target
```

点击“添加变量”，可以继续添加这些表达式，用逗号分隔多个变量：

```text
adc_data.volt.V_CHASS
adc_data.current.I_BAT
adc_data.current.I_LL
adc_data.adc_data_raw[0]
loop_var.P_BAT_target
loop_var.pwm_enabled
loop_var.energy_direction
PI_Volt_Controller.output
PI_Current_Controller.output
```

新增变量会先使用电脑上的 GDB 读取 ELF，识别类型和数组长度，不需要访问 MCU。例如本工程 `energy_direction` 是 **1 字节有符号枚举**，不会强行按 4 字节读取。原有 `AUTO` 设置继续使用；数值元素也可手动选择 `F32 / F64 / I8 / U8 / I16 / U16 / I32 / U32 / I64 / U64 / BOOL`，所选大小必须和 ELF 一致。

支持驻留 RAM 的全局变量、嵌套结构体、结构体数组、多维数值数组及其具体元素。结构体与数组是分组，每个勾选的数值成员是一条曲线。指针、位域、静态成员和成员函数不自动展开；不执行函数调用、不解引用指针，不解析当前栈帧的局部变量。优化掉的变量没有稳定内存地址，应使用带调试符号的 Debug ELF。

勾选待采样变量，点击“开始采样”。运行中可折叠/展开数组、查看光标值，修改勾选和添加/删除变量需要先点击“停止”；最多同时采样 32 个数值元素。

### 添加结构体或整个数组

停止采样，点击“添加变量”，直接输入数组名，例如：

```text
adc_data.adc_data_raw
adc_data.adc_data_mid
PI_Volt_Controller.error
```

也可直接添加 `adc_data`、`loop_var`、`PI_Volt_Controller`，按层展开结构体、嵌套成员与数组。例如：

```text
▼ adc_data
    ▼ volt
        adc_data.volt.V_CHASS
        adc_data.volt.V_CAP
    ▼ power
        adc_data.power.P_BAT
        adc_data.power.P_CHASS
```

实际行中使用完整成员名以便辨认。添加父结构体时，会合并已经单独添加的子成员，保留原来勾选状态，避免重复采样。只勾选需要的数值成员即可；结构体和数组分组本身不占采样通道。

界面会识别 ELF 中的长度，显示可折叠的父行和子元素，例如：

```text
▼ adc_data.adc_data_raw   [2]
    adc_data.adc_data_raw[0]
    adc_data.adc_data_raw[1]
```

点击数组名即可折叠/展开；勾选父行可以选择全部子元素，也可以逐个勾选。**折叠只隐藏行，已选中的子元素继续采样**。超过剩余采样名额的新数组默认不勾选，选择部分元素即可；数组中有部分元素已选时，父行不会显示为全部勾选。

支持最多 8 维、4096 个元素的数组，按维度递归展开；可以只添加某一行，例如 `matrix[0]`。递归展开最多 12 层、8192 个节点，较大的对象请直接添加所需子成员。所有已选数值合计最多 32 路。选择和展开状态保存到工程设置，重开后恢复。开始采样时核对分组定义并重新解析已选数值的地址与类型；若定义改变，需要删除相应分组并重新添加。

### 写入变量数值

1. 选择一个普通数值行，例如 `loop_var.V_target`、`loop_var.P_BAT_target` 或 `PI_Volt_Controller.K_p`。
2. 点击 **写入数值**，输入目标值，再点击对话框中的 **写入**。仅选中变量、悬停或采样都不会写入。
3. 插件重新从 ELF 核对该成员及父对象的类型、地址和 const 属性，执行一次 RAM 写入后读回，在状态栏报告结果。

支持自然对齐的 **8/16/32 位整数、32 位 float、bool**。整数可输入十进制或 `0x` 十六进制，bool 使用 true/false 或 1/0；拒绝越界、NaN/Inf、const 成员、整体结构体/数组、Flash/外设和64位写入。不修改相邻变量，不暂停/复位 MCU，不自动重试写入。演示模式禁用实际写入。

写入的是当前运行的 RAM，重新上电不会保存。变量若由中断或控制函数持续更新，下一控制周期可能覆盖刚写的值；状态栏出现“读回值已不同”时，不会反复重写。选用真正的目标参数或 PI 参数进行修改，并保持 ELF 与板上固件一致。常规波形采样仍只发送读取命令，写入使用同一个 OpenOCD 服务的独立短连接。

### 最大最小值与双游标测量

波形下方增加测量表。未开启双游标时，**最小值、最大值、峰峰值**按当前保留的采样记录统计，每500 ms更新一次；这是最多 20,000 帧的滚动范围，不是程序启动以来的永久极值。停止采样时会立即补算最终统计。

勾选 **双游标测量**，视图冻结，出现黄色 **A** 和粉色 **B** 两条竖线。按住竖线拖动即可移动，后台继续采样。两条线可以交换左右顺序；测量区间始终取两线之间，包含两端的实际采样帧。

- **Δt**：A/B对应采样时间之差的绝对值，显示为毫秒。
- **A值 / B值 / B−A**：两端的数值和带方向的数值差。
- **最小值 / 最大值 / 峰峰值**：两线之间全部有效点的统计，峰峰值 = 最大值 − 最小值。

例如 A值为24 V、B值为25 V，但区间曾出现26 V和23 V，则 **B−A = 1 V，峰峰值 = 3 V**，两者含义不同。空隙/NaN/Inf不参与极值统计；端点无效时A/B值或B−A显示“—”，不会用插值或零代替。点击“实时跟随”、双击波形、重新开始采样或清空曲线会释放双游标。

- **分轨 · 独立刻度**：默认模式，每路单独缩放，适合同时查看电压、电流、功率。
- **叠加 · 共用刻度**：所有变量使用同一纵轴，适合比较同单位的数据。
- **窗口 s**：改变显示的时间跨度。
- **悬停**：即时显示时间游标、采样点标记与数值框，不需要等待系统提示框；左侧“光标值”同步显示所有曲线在这一帧的值。
- **单击**：固定该时刻整帧数据并冻结视图，移开鼠标后“光标值”仍保留；再单击另一个位置可以重新选点。
- **左键拖拽**：沿时间轴移动波形，回看已记录的历史；只平移显示，不改采样数据。
- **鼠标滚轮**：以鼠标附近的时间为中心缩放横轴，最小显示跨度 10 ms；不会提高原始采样率。
- **实时跟随 / 双击波形**：释放固定读数、恢复设定的时间跨度，并跳回最新记录。
- **冻结显示**：保存当前这份历史供回看，后台仍采样；取消冻结也会返回实时跟随。20,000 帧后台滚动缓冲独立继续运行，查看历史不会暂停 MCU。
- **停止**：断开插件的 Tcl 连接并保留历史；不会停止 MCU，也不会关闭 CLion 的调试器。
- **清空曲线**：清除现有历史，不重启 MCU。
- **导出 CSV**：导出当前最多 20,000 帧的历史；冻结时导出冻结画面对应的历史。

状态栏显示实际采样率、单帧读取耗时、有效帧数和错误数。Windows 定时精度、USB、SWD 速度、变量数量都会影响实际采样率；实际采样间隔同时受设定周期与读取后预留的空闲时间限制。

光标显示的是**最近的实际采样帧**，不做插值；失败样本显示“—”，不会变成零或跨过空隙伪造读数。“同一列”指软件的一帧读取结果，多变量在底层仍可能先后读取，不能视为 MCU 同时采样的原子快照。历史只能在当前保存的数据范围内拖动；回到实时时会切换到仍在滚动的后台缓冲。

### 采样速度与界面负担

1.0.6 优先采用50 ms稳健采样、100 ms画面刷新、500 ms实时统计，减少通信与界面负担。以下高速和满速模式仍保留，适合在确实需要更多采样点且 CLion 流畅时手动启用。

**周期数值是目标，不代表实际采样速度。** 1.0.1 即使填 2 ms，每帧读完也至少等待 5 ms，并且等待时间不少于读取耗时。本机 Windows/JBR 的定时执行器还可能将很短的等待延长到约 15.6 ms，所以不能把“2 ms”理解为已经达到 500 Hz。

1. 安装 1.0.6 并重启 CLion，保留当前已经稳定的 OpenOCD 服务和 SWD 速度。
2. 停止插件采样，先保留 2～4 个需要观察的变量。
3. 勾选 **高速采样**，先用 **2 ms**，再尝试 **1 ms**，重新开始采样。如果 1 ms 已稳定，可再停止采样并将周期设为 **0 ms（满速）**；界面会自动勾选高速采样。
4. 看底部 **实际 Hz、读取 ms、错误数**。如果 Hz 不再提高，继续减小目标周期没有收益；可以减少变量数量或选择地址相邻的变量。
5. 如果满速没有带来实际 Hz 提升，恢复 1 ms 即可。如果通信再次不稳定，停止插件采样、恢复之前稳定的周期；也可以取消高速模式。0 ms 时取消高速模式会将周期恢复到 1 ms。

| 模式 | 每帧读完后的等待 | 作用 |
| --- | --- | --- |
| 稳健（默认） | 至少 5 ms，且不少于本帧读取耗时；同时满足目标周期 | 保留先前的总线空闲时间 |
| 高速 | 按目标周期扣除读取耗时后等待，至少让出 0.2 ms | 缩短空闲时间，提高实际采样率；SWD 占用更高 |
| 满速（高速 + 0 ms） | 无主动等待，读完一帧再发下一帧 | 尽量用满当前读取链路；多个 RAM 块共用一次 Tcl 请求 |

高速模式使用本机测试中精度更高的 `Thread.sleep`，不用忙等，也不积压落后的采样任务。Windows 仍可能延迟唤醒，不能保证严格 1 ms。网络回复的缓冲读取减少电脑端逐字节访问套接字的开销，SWD 仍为原来的对齐 32 位读取。

满速模式每次只保留一个正在读取的帧，由套接字读取等待数据，不用忙等或预先排队发送多个帧。多个 RAM 块的批量请求只减少电脑与 OpenOCD 之间的往返，**不减少底层 SWD 内存读取次数或保证变量同时取值**。任意块失败，整帧都记为空隙并停止；不会显示前半帧成功的数据。满速增加调试带宽和电脑端开销，其他调试功能可能响应变慢。演示模式仍保留短等待以限制电脑开销，其速度不能用来估算实物吞吐。

用户已反馈：1.0.2 高速 1 ms、4 个变量时实际约 **299 Hz**，读取约 **2～5 ms**，采样稳定。299 Hz 相当于平均约 3.34 ms 一帧，说明这时已主要受读取链路限制。满速能省去主动等待，是否有明显收益需要以状态栏实际 Hz 为准，不能据此承诺 1000 Hz 或更高。

**采样率与画面刷新率不同**：后台记录每个采样帧，1.0.6画面约每100 ms更新一次（目标约10次/秒），一次画面更新可显示多个新采样点；实时整段统计每500 ms计算一次，光标和测量线交互仍立即响应。新采样点较少时不会每次都重复复制相同历史。更快采样增加调试链路和电脑端占用，也不能保证多变量同时取值。20,000 帧历史在20 Hz时约保留1000秒，在500 Hz时约保留40秒。

满速模式通过本机模拟服务、真实 OpenOCD Tcl 协议与界面测试，**尚未在实物上确认最高速度及稳定性**。旧版安装包保留在 `dist`，可用于回退。

## 5. 这个版本如何避免“假尖峰”

每次“开始采样”都重新从当前 ELF 解析地址，不复用旧地址。运行中如果发现 ELF 文件变动，会停止采样，要求重新下载匹配固件后再开始。

ELF **必须与板上正在运行的固件匹配**。插件能够检测本地文件变化，但没有自动校验板上 Flash 与 ELF 是否一致。更新固件后请重新开始采样。

相邻变量会合并为 RAM 读取块，减少通信次数。读取失败立即停止并留下曲线空隙；CSV 对应单元格留空，不会把错误填成 0。NaN、Inf 也显示为空隙。

原有模式与单块读取使用：

```tcl
[target current] read_memory 0x20000000 32 <字数>
```

满速有多个 RAM 块时，用同一个 Tcl 请求组合这些读取，例如：

```tcl
join [list [[target current] read_memory 0x20000000 32 2] [[target current] read_memory 0x20000120 32 1]] {|}
```

`list`、`join` 只在电脑上的 OpenOCD 中组织回复文本，读取地址和字数仍来自经过校验的 RAM 计划。

采样地址和长度根据实际变量计算并按 4 字节对齐，单字节、半字字段从返回数据中按小端顺序提取。对齐后仍检查整个读取范围位于 STM32 RAM，不读取可能产生副作用的外设寄存器；采样不会发送 `halt`、`reset`、`resume`、下载或内存写指令。只有显式“写入数值”会使用 `write_memory`，随后读回核对。

“不暂停 CPU”仍会占用少量调试总线带宽，并且一次内存读取不是整个控制状态的原子快照。它适合看电压、电流、功率和软件控制环的变化，**不能代替示波器观察 200 kHz 栅极、电感纹波或极窄毛刺**。

## 6. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 连接被拒绝 | 检查顶部 `ST-LINK ▼` 是否已切换为 `OpenOCD Wave Scope`；仅选择 G474 不会切换调试服务。OpenOCD 日志应有 `Listening on port 6666 for tcl connections`。 |
| 连上但没有内存数据 | 查看 OpenOCD 日志，确认目标已完成初始化；优先使用上述 ST-Link DAP 配置。插件不会用暂停 CPU 的方式强行读取。 |
| 曲线一直不动 | MCU 是否停在断点、变量是否确实被更新、ELF 是否为板上固件对应的文件？ |
| 找不到变量 | 输入完整字段名，选择正确 Debug ELF；确认变量没有被优化掉。 |
| 读数明显不合理 | 先核对 ELF、自动识别类型和变量含义；不要使用旧构建的 ELF。 |
| 实际采样率低 | 在连接稳定时试用高速采样与较短周期；减少变量数量，相邻变量更容易合并读取。以状态栏 Hz 判断是否提速。 |
| 大负载时读内存失败、调试窗口显示 PC=0 | 先查看 OpenOCD 错误日志；PC=0 可能来自核心寄存器读取失败，不能单凭此图认定程序跳到了零地址。对比停止插件采样后是否仍出现；确认当前连接实际采用 480 kHz SWD，再检查 MCU 电源、复位线和 SWD 接线。 |
| 同时开着原来的 Live Watch | 可先关闭其采样，减少重复读内存的调试带宽。 |

大负载下若 MCU 仍正常运行，而 OpenOCD 间歇读取失败，应比较读取频率和驱动，再检查 SWD 信号完整性和参考地。当前已实测到这种现象；降至 480 kHz 后仍有失败，尚未确认唯一原因。字节和 32 位读取的对比短测都曾成功，不能据此认定某一种读取方式存在固定错误。

先用短线连接 SWCLK、SWDIO 和 MCU 附近的调试接口地，避开电感、MOS 开关节点及负载电流走线。调试器地线应回到 MCU 附近，避免接到负载或电源的大电流接线端来代替信号地。若继续失败，用示波器在 MCU 引脚附近观察 3.3 V、SWCLK 和 SWDIO 相对本地地的瞬态；负载仪、板上电源和电脑之间的接地关系也需要核查。
